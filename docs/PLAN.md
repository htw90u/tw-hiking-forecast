# 台灣登山氣象整合平台 — 實作規劃

> 狀態：規劃稿 v0.1（2026-10-23）
> 範圍：第一階段以中央氣象署（CWA）開放資料為主；Windy、系集預報列為後續擴充。

---

## 1. 結論摘要

- **目前沒有單一免費服務能完整滿足需求**（地形底圖 + CWA 網格疊圖 + 點擊查詢測站歷史 + 地點預報 + 地震/颱風 + 離線）。現有工具各自只解決一部分（見 §2）。
- 建議自建 **PWA（Progressive Web App）**：一套程式碼同時是網頁與可安裝到手機桌面的 App，以 Service Worker + IndexedDB 保存最近查詢資料，離線可查。
- 後端採 **排程抓取 → 產出靜態檔** 的無伺服器架構（Cloudflare Workers Cron + R2，或 GitHub Actions + Pages），全部可在免費額度內運作，CWA API 金鑰不外露到前端。
- 測站「歷史資料」CWA 開放 API 只提供近期/即時，**需自行逐時封存**，越早開始累積越好。

## 2. 現有免費資源評估

| 資源 | 可做到 | 缺口 |
|---|---|---|
| [CWA 登山天氣](https://www.cwa.gov.tw/V8/C/L/Mountain/Mountain.html) | 各山 72 小時/一週預報、溫度曲線 | 無地圖疊圖、無測站關聯、無離線 |
| CWA 全球資訊網 / 生活氣象 App | 雷達、雨量、衛星、地震、颱風 | 各圖獨立，無法與山名/等高線疊合 |
| Windy（已訂閱） | 多模式預報、ECMWF/GFS、部分雷達與衛星 | 無 CWA 網格與測站、地圖無台灣等高線細節；API 付費 |
| [Mountain-Forecast](https://www.mountain-forecast.com/maps/Taiwan) / meteoblue / Ventusky | 山頂點預報、全球模式圖 | 解析度不足，無 CWA 觀測 |
| 魯地圖 / OpenTopoMap / 國土測繪中心 WMTS | 等高線、步道、山名 | 無氣象圖層 |
| 國家災害防救科技中心「民生示警」 | CAP 警特報 | 非登山導向 |

→ 整合價值在於「**同一張地形圖上疊 CWA 網格 + 點擊得到該點所有資訊**」，此部分需自建。

### 3.4 非 CWA 補充

| 項目 | 來源 |
|---|---|
| 山名/山頂座標 | OpenStreetMap `natural=peak`（含百岳、小百岳） |
| 步道 | OSM `highway=path`、林業保育署步道資料 |

> ⚠ 本規劃撰寫環境無法直連 CWA 伺服器，以上資料集代碼依公開文件整理，實作第一步需以 [Swagger 文件](https://opendata.cwa.gov.tw/dist/opendata-swagger.html) 逐一驗證欄位與更新頻率。

## 4. 系統架構

```
            ┌──────────────── 排程 (Cloudflare Workers Cron, 每 10 分) ────────────────┐
CWA API ──► │ fetcher: 下載網格/觀測/預報/地震/颱風                                     │
            │ processor: 網格 → 彩色半透明 PNG + 數值 JSON；觀測 → 逐時封存            │
            │ spatial index: 山頂/步道/鄉鎮 ↔ 網格格點、地震震央距離                   │
            └──────────────► R2 / Pages（靜態檔 + latest.json 索引）◄──── 歷史 D1 (SQLite)
                                          │
                                          ▼
                   PWA 前端（MapLibre GL JS）
                   - 底圖 + 疊圖 + 透明度滑桿
                   - 點擊查詢、時間軸動畫
                   - Service Worker 快取 + IndexedDB 離線
```

選型理由：

- **Cloudflare Workers + R2 + D1**：免費額度足夠（每日 10 萬次請求、cron、5GB SQLite），金鑰存在 secrets。備案：GitHub Actions cron（排程可能延遲 5–15 分，適合非即時資料）。
- **MapLibre GL JS**：開源、支援向量/點陣圖磚、raster 圖層可直接設定 `raster-opacity` 做濃淡。
- **網格處理**：伺服器端將 CWA 網格依色階轉成 PNG（雷達 dBZ 用 CWA 標準色階，雨量用分級色階），同時保留數值 JSON 供點擊查值。
- **歷史資料**：CWA REST 只回傳最新觀測，因此每小時將 `O-A0001/0002/0003` 寫入 D1；更早期資料可手動從 CODiS（氣候資料服務系統）下載補入。

## 5. 介面設計（簡潔優先）

### 5.1 主畫面

```
┌─────────────────────────────────────┐
│ [搜尋山名/步道]            [⚠ 警報] │ ← 有颱風/地震/特報時亮起
│                                     │
│          地 圖（等高線底圖）         │
│                                     │
│  ◄ ━━━━━●━━━━━━ ►  -3h  現在 +1h   │ ← 時間軸（觀測→預報）
├─────────────────────────────────────┤
│ 圖層: [雷達][累積雨][QPF][溫度][雲圖]│ ← 單選 chip，透明度長按調整
└─────────────────────────────────────┘
```

- 一次只開一個主要氣象圖層，避免畫面混亂；測站、山名為可開關的點圖層。
- 透明度滑桿控制濃淡；色階圖例固定在角落。

### 5.2 點擊任一點 → 底部資訊卡

1. **地點**：最近山頂/步道、海拔（DEM）、所屬鄉鎮
2. **現在**：該格點雷達值、近 1/3/24 小時雨量
3. **鄰近測站**（3–5 站，依距離與海拔差排序）：溫度、風速、陣風、雨量
4. **預報**：CWA 登山/育樂景點預報（若附近有）> 鄉鎮預報
5. **歷史**：圖表，區間選 `24h / 3 天 / 7 天 / 自訂`
6. 按鈕：`收藏` `存離線` `開啟 Windy`

### 5.3 反向查詢：「哪些山在下雨」

- 選擇圖層後點「列出受影響山區」，以門檻值（例：雷達 ≥ 30 dBZ、1h 雨量 ≥ 10 mm、QPF ≥ 某值）列出落在範圍內的山名/步道，依強度排序。

### 5.4 地震

- 地圖標出震央、以圓圈標示 10/30/50 km 範圍，列出範圍內的山與步道，並顯示鄰近鄉鎮震度。
- 震度 ≥ 4 於山區，提示落石/坍方風險。

## 6. 離線策略

| 資料 | 方式 |
|---|---|
| App 本體 | Service Worker 預快取 |
| 最近查詢（點擊資訊卡、收藏點） | IndexedDB，保留最近 N 筆並標示「資料時間」 |
| 「存離線」行程 | 一次下載該區域：預報、測站近 7 天、最新雷達/雨量圖、底圖圖磚（限定縮放層級） |
| 底圖 | 線上底圖快取有限；長程離線建議仍以魯地圖 App 為主，PWA 提供「匯出 GPX/KML 標記點」 |

> 離線顯示時一律標示資料時間與「離線資料」標記，避免誤判為即時資訊。

## 7. 登山安全評估（規則式，第一版）

以燈號呈現，並列出觸發原因（不只給結論）：

| 因子 | 黃 | 紅 |
|---|---|---|
| 1h 雨量（觀測/預報） | ≥ 10 mm | ≥ 30 mm |
| 24h 累積雨量 | ≥ 80 mm | ≥ 200 mm（豪雨） |
| 陣風 | ≥ 10 m/s | ≥ 17 m/s |
| 體感溫度 | ≤ 5 °C | ≤ 0 °C |
| 颱風 | 海上警報 | 陸上警報 |
| 地震（50 km 內） | 震度 3–4 | 震度 ≥ 5 弱 |
| 警特報 | 大雨特報 | 豪雨以上、雷雨 |

門檻值可由使用者調整；此評估僅供參考，需於介面明示。

## 9. 風險與待確認事項

1. **QPF 網格**：CWA 開放資料中的定量降水預報可能僅提供圖片；若無網格版，影像需地理對位，點擊查值精度受限。
2. **CWA 使用規範**：遵守開放資料授權（政府資料開放授權條款），標示資料來源；不得高頻率重複請求。
3. **魯地圖圖磚授權**：網頁版若要使用需確認授權；否則以 OpenTopoMap / 國土測繪中心為底圖。
4. **Windy API** 為付費；先以深連結替代。
5. **歷史觀測**：自建封存前的資料需透過 CODiS 手動補入。
6. 山區測站稀疏，測站值需同時顯示海拔差，避免以平地測站推估高山狀況。
